## 1. Journal Approval VARCHAR/INT Bug — Full Fix

### Background
`fin_journal_details.journal_no` is a `VARCHAR(45)` column that stores values in two formats:
- Plain numeric: `'214244'`
- Prefixed with trailing space: `'JN-214244 '`

Stored procedures that compared this column against an `INT` parameter (`WHERE journal_no = jno`) forced MySQL to DOUBLE-cast the VARCHAR, producing:

```
Truncated incorrect DOUBLE value: 'JN-214244 '
```

This caused `Approval Error` on `StudentJournals.aspx?j=Journal`. A prior session had fixed `fin_ApproveJournal_Safe` but the page calls `fin_ApproveJournal` (a different procedure).

### Fix — Migration: `20260519_130000__accounts__fix_approve_journal_varchar.sql`

**Database:** `campus_dynamics_accounts`

Rewrote two routines with VARCHAR-safe WHERE pattern:

```sql
WHERE (TRIM(journal_no) = CAST(jno AS CHAR) OR TRIM(journal_no) = CONCAT('JN-', jno))
```

Routines fixed:
- `fin_GetJournalTotalCR_DR` (function)
- `fin_ApproveJournal` (procedure) — also removed a redundant `INNER JOIN fin_journalnumbers` from its INSERT...SELECT

### Fix — Migration: `20260519_140000__accounts__fix_journal_no_text_nullable.sql`

Three more procedures had the same bug. Additionally, the user requested the column itself be made TEXT and nullable.

**Column change:**
```sql
ALTER TABLE fin_journal_details MODIFY COLUMN journal_no TEXT NULL;
-- was: VARCHAR(45) NOT NULL DEFAULT '-'
```

**Procedures fixed** (parameter type changed from `INT` to `TEXT`; WHERE clauses updated):

| Procedure | Bug location |
|---|---|
| `fin_ClearJournalDetails` | `DELETE ... WHERE journal_no = jno` |
| `fin_GetJournalDetails` | `SELECT ... WHERE journal_no = jno AND journal_type = jType` |
| `fin_ValidateAndPostJournal` | Three occurrences: COUNT(*), SUM DR, SUM CR |

All WHERE clauses now use the safe pattern:
```sql
WHERE TRIM(journal_no) = TRIM(jno)
   OR TRIM(journal_no) = CONCAT('JN-', TRIM(jno))
```

For lookups into `fin_journalnumbers` (which has INT `JournalNo`):
```sql
WHERE JournalNo = CAST(TRIM(jno) AS UNSIGNED)
```

### 2a. Remove acad_CompletionCheck Gate

**File:** `App_Code/AcademicDocuments/AcademicDocumentPdfService.cs`

The `EnsureClassicGraduandLinkIfMissing()` method previously required students to have a completion record before auto-inserting into `acad_graduands`. This blocked enrolled (non-graduated) students from generating transcripts.

**Fix:** Removed the `acad_CompletionCheck` existence condition from the INSERT query. Students are now eligible for transcript generation if they exist in `acad_student` and have results in `acad_results`.

### 2b. Auto-refresh `acad_transcript_results` Before Every PDF

**File:** `App_Code/AcademicDocuments/AcademicDocumentPdfService.cs`

`acad_transcript_results` is a separate materialized table (not a view of `acad_results`). The transcript column stored procedures (`acad_GetSingleStudentTranscript_Col1/Col2`) query this table, not `acad_results` directly. If a student's results were entered after the last call to `acad_CreateTranscript`, the PDF would show empty rows.

**Fix:** `EnsureClassicGraduandLinkIfMissing()` now always calls `acad_CreateTranscript` before generating the PDF, regardless of whether the table was empty:

```csharp
using (MySqlCommand createCmd = new MySqlCommand(
    "CALL acad_CreateTranscript(@reg, 'Normal', 0)", conn))
{
    createCmd.CommandTimeout = 120;
    createCmd.Parameters.AddWithValue("@reg", safeRegno);
    createCmd.ExecuteNonQuery();
}
```

## 3. License Expiry — Full Implementation

### 3a. How the System Works

The license mechanism:

1. `fin_expdates` table in `campus_dynamics_portal` DB stores `expDate` (DATE) and `lastLogin` (DATE)
2. `Licensing.Settings()` (`App_Code/Licensing.cs`) compares `expDate` to `DateTime.Today`:
   - `expDate > today` AND `lastLogin <= today` → valid → updates `lastLogin` → returns `true`
   - `expDate <= today` → expired → returns `false`
   - `lastLogin > today` → system date backdated → returns `false`
3. `LoginLoader.PageLocator()` calls `Licensing.Settings()`:
   - `true` → loads login form (`lg_modern.ascx` / `lg.ascx`)
   - `false` → loads Locker screen (`Locker.ascx`)
4. Locker screen shows NTL contact details and an activation code input
5. Activation code = new expiry date encrypted with TripleDES/ECB, passphrase `"kasoka"`, Base64-encoded
6. Entering a valid code calls `Licensing.UpdateLicense()` → decrypts → writes new `expDate`

### 3b. Bug: Main ERP Read From Wrong Table

**File:** `App_Code/AccessControl.xsd` (main ERP)

The main ERP's `AccessControl.xsd` used bare `fin_expdates` in all SQL queries via `vacConnectionString` → `campus_dynamics` DB. The portal reads from `campus_dynamics_portal.fin_expdates`. These were two separate rows — renewing via one Locker screen did not update the other.

**Fix:** Updated all 8 `<CommandText>` elements in the main ERP's `AccessControl.xsd` to use the fully-qualified table name:

```sql
-- Before
SELECT expDate FROM fin_expdates
UPDATE `fin_expdates` SET `lastLogin` = @lastLogin

-- After
SELECT expDate FROM campus_dynamics_portal.fin_expdates
UPDATE campus_dynamics_portal.fin_expdates SET `lastLogin` = @lastLogin
```

All reads and writes (SELECT expDate, SELECT lastLogin, UPDATE lastLogin, UPDATE license, DELETE, INSERT, full-row UPDATE) now target the shared `campus_dynamics_portal.fin_expdates` table regardless of which DB `vacConnectionString` is connected to. One renewal code entered in either portal's Locker screen now unlocks both.

> **Note:** `DbObjectName="hoteldynamics.fin_expdates"` in the XSD `<DbSource>` attributes and `DataSourceName` in `<Parameter>` attributes are VS designer metadata only — they have no runtime effect and were left as-is.

### 3c. Bug: New Screens (SidebarMaster) Had No Auth or License Gate

**File:** `COOPERP/NewScreens/SidebarMaster.master.cs`

Every legacy module master page (`Faculty/MasterPage.master.cs`, `accounts/MasterPage.master.cs`, etc.) checks `Session["username"] == null` and redirects to `~/Default.aspx`. `SidebarMaster.master.cs` — used by all new screens — was missing this check entirely. New-screen pages were accessible without authentication, bypassing the license gate.

**Fix:** Added at the top of `Page_Load`:

```csharp
if (Session["username"] == null)
{
    Response.Redirect("~/Default.aspx");
    return;
}
```

When `Default.aspx` loads, it calls `LoginLoader` → `Licensing.Settings()`. If expired, the Locker shows.

### 3d. Bug: Portal's `IsAlreadyLoggedIn()` Bypassed License Check

**File:** `CampusDynamics_Portal/Default.aspx.cs`

The portal's `Default.aspx.cs` calls `IsAlreadyLoggedIn()` before `LoadControls()`. If the user had an active session or a valid Forms auth cookie, `IsAlreadyLoggedIn()` redirected straight to `MyApplications_Modern.aspx` without ever calling `Licensing.Settings()`. Logged-in users could open the portal freely after the license expired.

**Fix:** Added license gate at the top of `IsAlreadyLoggedIn()`:

```csharp
private bool IsAlreadyLoggedIn()
{
    // License gate: if expired, never shortcut past the Locker
    if (!Licensing.Settings())
        return false;

    // 1) Active session — straightforward
    if (Session["username"] != null)
    { ... }
}
```

When expired, `IsAlreadyLoggedIn()` returns `false` → `LoadControls()` runs → Locker shows.

### 3e. Bug: `PortalMaster` Had No License Check — Authenticated Pages Unprotected

**File:** `CampusDynamics_Portal/PortalMaster.master.cs`

`PortalMaster` is the master page for all authenticated portal pages (`MyApplications_Modern.aspx`, `StudentResults.aspx`, `StudentFees.aspx`, etc.). It only checked `Session["username"]` for auth. A user already on an interior portal page with an active session could continue using the portal indefinitely after the license expired.

**Fix:** Added at the very top of `Page_Load`, before any session or auth logic:

```csharp
protected void Page_Load(object sender, EventArgs e)
{
    // License gate — must pass before any session or page logic runs.
    if (!Licensing.Settings())
    {
        Response.Redirect("~/Default.aspx");
        return;
    }

    // Auth check — redirect to login only if no session at all.
    if (Session["username"] == null)
    { ... }
```

Every request to any authenticated portal page now checks the license first. When expired, the user is redirected to `Default.aspx` → Locker.

## 6. How to Renew the License

1. Client contacts Newline Technologies Limited
2. NTL generates an activation code:
   - Take the new expiry date string, e.g. `"2026-12-31"`
   - Encrypt: `encrypter.EncryptData("2026-12-31")` using TripleDES/ECB, passphrase `"kasoka"` → Base64 string
3. Client pastes the code into the Locker screen text box and clicks **Activate**
4. System decrypts → writes new `expDate` to `campus_dynamics_portal.fin_expdates`
5. Page redirects to `Default.aspx` → `Licensing.Settings()` returns true → login form shows
6. Both portals unlock simultaneously (single shared table)
